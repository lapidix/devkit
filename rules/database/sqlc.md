# sqlc, pgx and goose

PostgreSQL from Go (`rules/database/postgres.md`): queries written as SQL, Go code generated by sqlc, pgx as the driver, goose for migrations.

## Files

```
migrations/                                   goose migrations: the schema's one source
sqlc.yaml                                     one sql entry per module
internal/infrastructure/database/             pool, transactions, IsUniqueViolation, dbtest
internal/modules/user/adapters/out/persistence/
├── queries.sql                               this module's queries
├── sqlcgen/                                  generated by sqlc, committed
├── user_repository.go
└── mapper.go
```

```yaml
# sqlc.yaml
version: "2"
overrides:
  go:
    overrides:
      - db_type: uuid
        go_type: github.com/google/uuid.UUID
      - db_type: timestamptz
        go_type: time.Time
      - db_type: timestamptz
        nullable: true
        go_type:
          type: time.Time
          pointer: true
sql:
  - engine: postgresql
    schema: migrations # sqlc reads goose files and skips their Down sections
    queries: internal/modules/user/adapters/out/persistence/queries.sql
    gen:
      go:
        package: sqlcgen
        out: internal/modules/user/adapters/out/persistence/sqlcgen
        sql_package: pgx/v5
        omit_unused_structs: true # only the types this module's queries use
```

- **Generated code is committed.** A Go repository is expected to build with `go build ./...` straight after cloning, and sqlc's documentation recommends committing. CI regenerates and fails on a diff (`rules/go/tooling.md`).
- `sqlcgen` is imported only by its own `persistence` package; the mapper turns its rows into the domain (`rules/go-server/adapters.md`).
- Every entry reads the whole `migrations/` folder, so without `omit_unused_structs` each module's `sqlcgen` would hold every other module's tables, and a new migration would rewrite them all.
- Types: `uuid` → `uuid.UUID`, which the mapper turns into the domain's string; `timestamptz` → `time.Time`, nullable as a pointer; `bigint` → `int64`; a PostgreSQL enum → a generated string type with a `Null…` variant for optional parameters.

## Queries

```sql
-- name: ListUsers :many
SELECT * FROM users
WHERE sqlc.narg(status)::user_status IS NULL OR status = sqlc.narg(status)
ORDER BY created_at DESC, id DESC
LIMIT sqlc.arg(page_size)::bigint OFFSET sqlc.arg(page_offset)::bigint;

-- name: UpsertUser :exec
INSERT INTO users (id, nickname, status, created_at, withdrawn_at)
VALUES ($1, $2, $3, $4, $5)
ON CONFLICT (id) DO UPDATE SET
  nickname     = EXCLUDED.nickname,
  status       = EXCLUDED.status,
  withdrawn_at = EXCLUDED.withdrawn_at,
  updated_at   = now();
```

- An optional filter is `sqlc.narg(x)` with `IS NULL OR`; only a query sqlc cannot express is written by hand in the repository.
- `LIMIT` and `OFFSET` are cast to `bigint` so the parameters are `int64`, which an `int` converts to without an overflow warning.
- **`updated_at` is the query's job**: sqlc has no ORM to fill it. The column defaults to `now()`, and every update sets `updated_at = now()`. `created_at` comes from the aggregate.

## Connection and transactions

```go
// internal/infrastructure/database/database.go
func (d *DB) Conn(ctx context.Context) Executor { //nolint:ireturn // the open transaction or the pool: two concrete types
	if tx, ok := ctx.Value(txKey{}).(pgx.Tx); ok {
		return tx
	}
	return d.pool
}

func (d *DB) Run(ctx context.Context, fn func(ctx context.Context) error) error {
	if _, ok := ctx.Value(txKey{}).(pgx.Tx); ok {
		return fn(ctx) // join the transaction already open
	}
	return pgx.BeginFunc(ctx, d.pool, func(tx pgx.Tx) error {
		return fn(context.WithValue(ctx, txKey{}, tx)) // rolled back when fn returns an error or panics
	})
}
```

- `Executor` has the methods sqlc's `DBTX` needs (`Exec`, `Query`, `QueryRow`), so a repository builds its queries per call: `sqlcgen.New(r.db.Conn(ctx))`.
- `*DB` satisfies every module's `TransactionRunner` (`rules/go-server/application.md`).
- The pool comes from `pgxpool` with `MaxConns` set to `DATABASE_POOL_SIZE`.
- **Behind a transaction-mode pooler** (`rules/database/postgres.md`), set `DefaultQueryExecMode` to `pgx.QueryExecModeExec` on the connection config: pgx otherwise caches named prepared statements, which the pooler loses between transactions.

## Errors

```go
// internal/infrastructure/database/errors.go
func IsUniqueViolation(err error, constraint string) bool {
	var pgErr *pgconn.PgError
	return errors.As(err, &pgErr) && pgErr.Code == uniqueViolation && pgErr.ConstraintName == constraint
}
```

- Repositories recognize constraint violations through this one helper, by the constraint's name, and return the matching domain error. `pgx.ErrNoRows` becomes the module's not-found error.
- Constraint names follow `rules/database/postgres.md` (`users_nickname_key`) and are written in the migration, since there is no ORM to choose them.

## Migrations

```sql
-- migrations/20261001000000_create_users.sql
-- +goose Up
CREATE TYPE user_status AS ENUM ('active', 'withdrawn');

CREATE TABLE users (
  id           uuid        PRIMARY KEY,
  nickname     text        NOT NULL,
  status       user_status NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now(),
  updated_at   timestamptz NOT NULL DEFAULT now(),
  withdrawn_at timestamptz,
  CONSTRAINT users_nickname_key UNIQUE (nickname)
);

-- admin user list: by status, newest first
CREATE INDEX users_status_created_at_idx ON users (status, created_at);
```

- One file per migration, SQL after `-- +goose Up`, named `YYYYMMDDHHMMSS_{verb}_{target}.sql` (`rules/database/conventions.md`). A backfill that SQL cannot express can be a goose Go migration.
- goose runs from `tools/go.mod`: `go tool -modfile=tools/go.mod goose -dir migrations postgres "$DIRECT_URL" up`, with `DIRECT_URL` the database itself when a pooler is in front (`rules/database/postgres.md`), and `DATABASE_URL` otherwise.
- An agent writes migration files and applies them only to its own local database; a person applies them anywhere shared (`rules/database/conventions.md`).
